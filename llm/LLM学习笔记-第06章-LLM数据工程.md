# LLM 学习笔记：第 6 章——LLM 数据格式、构造与质量控制

## 1. 数据不是一个文件夹，而是一条生产线

```text
网页/书籍/代码/论文/对话
  ↓ 获取与授权
解析正文 → 语言识别 → 质量过滤 → 隐私/安全过滤
  ↓
精确去重 + 模糊去重 + 基准污染检测
  ↓
领域与语言配比 → Tokenize → Packing → Sharding
  ↓
训练集 / 验证集 / 测试集 + 数据谱系记录
```

模型不会自动判断“这是广告模板还是可靠知识”。数据管线决定它反复看见什么。

## 2. 不同阶段的数据格式

### 预训练/CPT：连续 Token

```json
{"text": "自然语言处理是人工智能的重要方向……"}
```

Tokenize 后将许多文档连接或 Packing 成固定长度序列。文档间加入 `<eos>`，并决定是否允许跨文档 Attention。

### SFT：消息或指令—回答

```json
{"messages": [
  {"role": "system", "content": "你是严谨的助手。"},
  {"role": "user", "content": "解释交叉熵。"},
  {"role": "assistant", "content": "交叉熵衡量……"}
]}
```

也常见 Alpaca 格式：

```json
{"instruction":"解释交叉熵","input":"","output":"……"}
```

最终都要通过 Chat Template 变成 Token 序列。通常只对 Assistant 回复计算 Loss；若对用户问题也算 Loss，模型会学习复述用户角色。

### 偏好数据

```json
{
  "prompt": "如何处理……？",
  "chosen": "更好的回答",
  "rejected": "较差的回答"
}
```

可来自人工比较、规则验证、强模型评审或混合方案。需要防止评审偏好长度、华丽格式或特定措辞。

### RL 可验证数据

```json
{
  "prompt": "求解方程……",
  "answer": "42",
  "verifier": "exact_match_or_unit_test"
}
```

数学、代码等任务可用答案检查器或单元测试提供奖励；开放问答通常需要奖励模型或评审器。

## 3. 预训练数据来源

| 来源 | 优势 | 风险 |
|---|---|---|
| Common Crawl/网页 | 规模大、覆盖广 | 噪声、重复、版权、隐私 |
| Wikipedia | 结构清晰、多语言 | 风格和领域有限 |
| 书籍 | 长文本连贯 | 授权与版权 |
| 论文 | 技术密度高 | 格式解析困难 |
| 代码仓库 | 代码能力 | 许可证、密钥、重复 fork |
| 问答/论坛 | 交互性强 | 质量不一、个人信息 |
| 合成数据 | 可控、易扩展 | 教师错误、模式坍缩 |

公开数据集示例：C4、The Pile、RedPajama、FineWeb、Dolma、SlimPajama、OSCAR、StarCoderData。使用前必须核对具体版本、来源、许可证和删除请求机制；“可下载”不等于“可随意商用”。

## 4. 清洗与质量过滤

```text
文档
├─ 乱码率高？          → 删除
├─ 字母/符号比例异常？ → 删除或进入代码管线
├─ 广告/导航模板多？   → 正文抽取
├─ 语言不匹配？        → 分类到对应语言
├─ 内容过短/重复？     → 删除
└─ 质量模型得分        → 保留/降采样
```

规则过滤可解释但僵硬；模型过滤更灵活，却可能将少数语言、口语或边缘观点错误判为低质量。应按语言和领域单独审计。

## 5. 去重为什么重要？

重复内容会：

- 浪费训练计算；
- 让模型过度记忆特定文本；
- 增加隐私与版权复现风险；
- 造成训练—测试污染。

```text
精确去重：Hash(规范化文档) 相同
近似去重：MinHash/LSH 比较 n-gram 集合相似度
局部去重：模板或段落重复
代码去重：fork、vendor、生成文件
```

去重粒度过强也会误删合法复述和稀缺语言材料。

## 6. 数据配比与采样

自然分布可能由英语网页和重复代码主导。训练通常人为设置权重：

```text
最终采样分布
├── 通用网页 45%
├── 代码 20%
├── 数学/科学 10%
├── 书籍 10%
├── 多语言 10%
└── 其他 5%          （纯示意，不是推荐配方）
```

上采样能提高稀缺领域出现频率，但重复看相同数据可能过拟合。需要监控每个来源的 epoch 数和边际收益。

## 7. 数据量与参数量关系

不能仅用“模型参数 × 20”作为普适真理。Chinchilla 的计算最优研究给出重要量级直觉，但真实项目还要考虑：

- 数据质量和可用唯一 Token；
- 训练后模型会被推理多少次；
- 小模型多训练可能降低长期部署成本；
- 模型架构与目标领域；
- 数据重复与课程学习。

```text
固定计算预算：参数 ↑ → 可训练 Token ↓
固定参数规模：数据 ↑ → 训练计算 ↑，直到边际收益很小
```

## 8. Packing 与 Loss Mask

若每条 SFT 样本很短，直接 Padding 会浪费计算：

```text
低效：[样本A PAD PAD][样本B PAD PAD]
Packing：[样本A EOS 样本B EOS 样本C ...]
```

必须正确设置：

- 文档边界和位置 ID；
- 是否跨样本注意；
- 哪些 Token 计算 Loss；
- Padding 不参与 Loss；
- 用户、系统、工具结果是否参与 Loss。

## 9. 合成数据的正确用法

```text
种子任务 → 教师模型生成 → 规则/执行器验证
          → 去重与难度筛选 → 人工抽检 → 混入训练
```

风险包括教师幻觉、语言风格单一、错误被放大、训练模型只会模仿表面格式。可验证任务更适合大规模合成。

## 10. 污染、隐私与许可证

```text
训练语料 ∩ 评测题库 ≠ ∅  → 指标虚高
训练语料含个人信息       → 记忆与泄露风险
训练语料许可证不兼容     → 法律/分发风险
```

需要保存 URL、抓取时间、许可、过滤理由、数据版本和删除链路。数据卡应说明已知限制，而非只给 Token 总数。

## 11. 数据验收清单

- 编码是否可逆，Tokenizer 对各语言是否公平？
- 精确/近似重复率是多少？
- 各来源、语言、领域、时间分布是什么？
- 基准污染如何检测？
- 是否有 PII、密钥、恶意代码和高风险内容扫描？
- SFT 角色模板和 Loss Mask 是否正确？
- 偏好标注者一致性、长度偏差如何？
- 是否保存数据谱系和许可证？
