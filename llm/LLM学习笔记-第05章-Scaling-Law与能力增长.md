# LLM 学习笔记：第 5 章——Scaling Law 与能力增长

## 1. 什么是 Scaling Law？

Scaling Law 是经验规律：在一定范围内，训练损失会随模型参数 `N`、数据量 `D`、计算量 `C` 增加而呈近似幂律下降。

```text
Loss
│\
│ \
│  \__                         双对数坐标中近似直线
│     \____
└────────────→ 参数/数据/计算
```

概念形式：

```text
L(N) ≈ L∞ + aN^-α
L(D) ≈ L∞ + bD^-β
```

这不是说参数翻倍、能力翻倍，而是平均预测损失以可拟合趋势持续改善。

## 2. 三个旋钮与一个预算

```text
固定训练计算预算 C
        │
        ├── 更多参数 N：每个 Token 计算更贵
        └── 更多数据 D：训练步数更多

粗略训练 FLOPs ∝ N × D
```

参数太大、数据太少：模型没有被充分训练；参数太小、重复数据太多：容量成为瓶颈。

## 3. Kaplan Law 与 Chinchilla 的差异

Kaplan 等人发现模型、数据和计算存在稳定幂律，并认为在其设置下，大模型具有较高样本效率。Chinchilla 工作重新研究固定计算下的最佳分配，发现当时许多大模型“参数太大、数据不足”；其实验结论是参数量和训练 Token 应更接近同比例增长。

```text
同样计算预算
旧倾向：更大的模型 + 相对较少数据
Chinchilla：较小模型 + 更多训练 Token
```

Chinchilla 70B 使用与 Gopher 280B 相近训练计算但更多数据，并在大量任务上更好。这不等于“永远固定 20 Token/参数”；具体最优点受数据质量、架构、重复训练、推理成本和目标任务影响。

## 4. 为什么规模增大能带来能力？

可以从四层理解：

```text
更多数据 → 看见更多语言、事实、代码与任务模式
更多参数 → 有容量压缩更多规律和组合
更多计算 → 有机会把参数拟合到数据
统一目标 → 各种模式通过 next-token 共享表示
```

大模型还能在上下文中使用示例：参数中学到的不是单一任务答案，而可能包含“根据文本模式识别任务并继续”的能力。

## 5. “涌现能力”真的突然出现吗？

某些离散指标看起来有阈值：

```text
准确率
│            ●●●
│         ●
│________●____________→ 模型规模
```

但要谨慎：

- 精确匹配把“几乎正确”也记为 0，可能制造跳变；
- 任务存在随机基线，低于阈值时都看起来一样差；
- Prompt 与解码策略会移动阈值；
- 平滑的损失改善可被下游非线性指标放大。

合理表述是：一些任务性能随规模呈明显非线性或阈值现象，但是否属于本质上的不连续“涌现”取决于指标和定义。

## 6. 为什么 GPT-3 看起来能力剧增？

不是单因果：

```text
175B 参数
 + 约 300B 训练 Token（论文披露的训练混合与采样）
 + 自回归统一目标
 + 大规模算力与优化
 + 提示中任务描述/示例
 = 显著增强的 zero/one/few-shot 表现
```

GPT-3 论文的突出贡献是系统展示 in-context learning 随规模改善，而非宣称模型在所有任务都可靠。

## 7. 数据质量为何能改变 Scaling？

1T 个低质量重复 Token 不等于 1T 个高质量、覆盖广的 Token。

```text
原始网页
├── 重复模板、广告、乱码        → 浪费计算
├── 错误、低信息密度内容        → 学到噪声
├── 高质量教材、代码、论文      → 更高学习价值
└── 稀缺语言/领域               → 决定覆盖能力
```

数据去重、配比、质量过滤和课程安排会改变相同 Token 预算的收益，因此不能只比较公开报告中的总 Token 数。

## 8. 训练 Scaling 与推理 Scaling

```text
训练时 Scaling：更多参数/数据/计算 → 更强基础模型

推理时 Scaling：同一模型在回答前使用更多计算
├── 多次采样 + 投票
├── 搜索/树探索
├── 更长推理轨迹
├── 验证器筛选
└── 工具调用
```

后者能提升复杂任务，但延迟与成本上升，而且“写得更长”不自动等于“推理更正确”。

## 9. 规模不是全部

| 因素 | 可能影响 |
|---|---|
| Tokenizer | 多语言与代码编码效率 |
| 数据配比 | 数学、代码、语言和知识覆盖 |
| 架构 | MoE、GQA、上下文效率 |
| 优化稳定性 | 是否充分利用计算预算 |
| SFT/偏好优化 | 指令遵循与回答风格 |
| 推理系统 | 量化、并行、KV Cache、工具 |
| 评测污染 | 看似能力提升但其实见过答案 |

## 10. 规划一个训练实验

不要直接训练最大模型。先训练一组小模型拟合趋势：

```text
参数：100M / 300M / 1B
数据：1B / 3B / 10B Token
             │
             ▼
记录验证损失、任务指标、训练 FLOPs
             │
             ▼
拟合经验曲线 → 预测大规模配置 → 留安全余量
```
