# 第 9 章：原生多模态模型

> “原生多模态”最重要的不是宣传名称，而是视觉是否从基础预训练阶段进入统一模型能力建设。本章以 Qwen3.5 为公开案例，同时说明它不意味着没有视觉组件。

## 1. 三种路线

```text
模块拼装式
纯文本 LLM + 预训练视觉塔 + 后训练连接器
        ↓
深度融合式
多层视觉特征 / Cross-Attention / 联合解冻
        ↓
原生多模态
基础预训练阶段持续混合文本、图片、视频并统一优化
```

边界并非绝对。一个原生多模态系统仍可能有视觉编码器、投影层和不同并行策略；判断关键是训练生命周期与能力是否统一。

## 2. 为什么模块拼装式先流行

- 可复用成熟 LLM 和视觉基础模型；
- 只训练 Projector 就能快速验证；
- 算力和数据门槛较低；
- 模块易替换和调试。

局限：视觉可能是“后加入的外语”，文本能力与视觉能力分别形成；连接瓶颈、视觉 Token 利用和深层推理可能受限。

## 3. 原生多模态的判定问题

至少检查：

1. 基础预训练是否包含大量图像/视频，而非仅 Post-training；
2. 视觉和文本是否共享长期训练目标与参数更新；
3. 是否用统一上下文完成文本、视觉推理和 Agent；
4. 多模态数据是否参与 Scaling 和数据配比；
5. 官方是否披露具体融合方式，而非只给产品标签。

“模型能看图”“端到端 SFT”“API 统一”都不足以单独证明原生多模态。

## 4. Early Text-Vision Fusion

原生路线把视觉表示较早放入统一预训练序列：

```text
纯文本 Tokens ─┐
图像 Tokens ───┼→ 混合数据调度 → 统一 Backbone → 预测目标
视频 Tokens ───┘
```

它的目标是让语言、视觉、推理和工具能力共同成长，而不是先把 LLM 完全训练好再补视觉课程。

## 5. 仍然需要视觉编码

像素与文字的统计结构不同。即使原生多模态，系统通常仍需要：

- 图片解码、Resize、Normalize；
- Patch/视觉 Token 化；
- 空间与时间位置；
- 视觉前端或专用视觉计算；
- 控制视觉 Token 数量。

“原生”描述训练与融合范式，不表示原始像素和文字必须经过完全相同的第一层。

## 6. Qwen3.5 公开架构

Qwen3.5 官方发布的首个开放权重版本为 `397B-A17B`：

```text
总参数约 397B
每次前向激活约 17B
高稀疏 MoE
Gated DeltaNet + Gated Attention 混合
Multi-Token Prediction
原生文本/图像/视频预训练
```

`A17B` 不是模型文件只有 17B，也不是显存只按 17B 计算。未激活专家权重仍需存储或分布到设备。

## 7. Gated DeltaNet 与 Attention

标准注意力对长上下文有较高 KV Cache 与序列成本。线性注意力/状态更新路线尝试用递归状态高效汇总历史；但精确内容检索和某些推理仍受益于标准 Attention。

Qwen3.5 使用混合层：

```text
多数高效 Gated DeltaNet 层：降低长序列成本
部分 Gated Attention 层：保留强检索与交互
```

门控让网络学习信息写入、保留和读取。具体层比例和实现以对应配置/官方报告为准。

## 8. MoE 在原生多模态中的作用

Router 为 Token 选择少数专家：

```text
文本/视觉 Token → Router → Top-k Experts → 加权合并
```

可能形成某些模态或能力偏好，但不能在没有分析证据时声称某专家“只负责图片”。训练还要处理负载均衡、视觉/文本 Token 数差异和 Expert Parallel 通信。

## 9. Multi-Token Prediction

普通 Causal LM 训练下一个 Token；MTP 增加预测更远未来 Token 的辅助目标，可改善训练信号，并为推测解码提供候选。用于多模态时，视觉上下文也影响多个未来文本 Token。

MTP 不等于一次永久确定多个输出；实际推理仍需验证或按实现解码。

## 10. 数据混合

原生预训练需要同时安排：

- 高质量纯文本，保持语言和知识；
- 图片—文字对；
- 交错图文文档；
- OCR、图表、STEM；
- 视频与时间数据；
- 多语言和代码；
- 后续指令、Agent 与 RL 数据。

若视觉 Token 太多，可能挤占文本训练计算；若纯文本占比过高，模型可能语言强但不依赖视觉。配比应按 Token、算力和能力目标，而非只按样本条数。

## 11. 异构训练基础设施

视觉和语言模块最佳并行方式可能不同：视觉侧受高分辨率和不等长输入影响，MoE 语言侧需要 Expert Parallel 和 All-to-All。

Qwen3.5 官方描述异构基础设施会为视觉与语言解耦并行策略，并利用稀疏激活重叠计算；FP8 流水线对敏感层保留 BF16，并监控稳定性。

这属于系统与算法联合设计：架构可训练，不代表朴素框架就能高效复现。

## 12. 原生多模态训练阶段

```text
统一基础预训练：文本+图像+视频
  ↓
中期训练/长上下文/能力专项
  ↓
多模态 SFT：问答、OCR、Agent、工具
  ↓
偏好优化与异步 RL：文本、多模态、多轮
```

“原生”不取消 SFT/RL；它改变的是视觉能力从何时开始进入模型。

## 13. 与模块化路线比较

| 维度 | 模块拼装 | 原生多模态 |
|---|---|---|
| 起点 | 已训练 LLM + 视觉塔 | 基础阶段混合模态 |
| 训练门槛 | 较低 | 极高 |
| 模块替换 | 容易 | 可能更耦合 |
| 视觉语言协同 | 依赖连接器和后训练 | 从预训练共同形成 |
| 纯文本保护 | 冻结 LLM 较容易 | 依赖数据配比和优化 |
| 深层多模态推理潜力 | 可能受后接入限制 | 统一学习潜力更高 |
| 可解释与调试 | 模块边界清晰 | 故障定位更复杂 |

不能只凭“原生”断言效果更好，仍需同规模、同数据和同评测比较。

## 14. 原生全模态与原生视觉语言

- 原生视觉语言：重点是文本、图片、视频；
- 原生全模态：还可能统一音频输入/输出、视觉生成等。

输入支持和输出支持要分别列出。能理解音频不等于能实时语音生成；能理解图片不等于能生成图片。

## 15. 如何评估原生优势

1. 同规模纯文本能力是否保持；
2. 视觉问题是否真正依赖图片；
3. 视觉与文字交错长上下文；
4. 多步视觉推理与工具调用；
5. 图片/视频加入后的延迟增量；
6. 不同模态混合时是否互相干扰；
7. Base、Instruct、Thinking 版本分别评估；
8. 与模块式强基线在同设置比较。

## 16. 常见误区

1. 原生多模态等于没有视觉编码器；
2. 所有参数对每个 Token 都激活；
3. A17B 表示权重只占 17B；
4. 线性注意力完全取代标准注意力；
5. 基础预训练含图片就无需 SFT；
6. 统一 API 就是统一底层模型；
7. 原生模型必然更易微调部署；
8. 从 Benchmark 可以反推出未公开架构。

## 17. 总结与复习

```text
原生多模态的核心：视觉从基础预训练阶段进入统一能力建设。
它仍需视觉处理、位置编码、Token 管理和后训练。
Qwen3.5 公开案例结合早期图文融合、混合高效注意力、MoE 与 MTP。
判断原生优势必须看同设置能力、模态干扰和系统成本。
```

复习：什么证据能支持“原生”？为什么仍需视觉前端？A17B 如何理解？混合 Attention 为何存在？多模态数据为何应按 Token/算力配比？
