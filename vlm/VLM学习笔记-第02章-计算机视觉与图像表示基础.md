# 第 2 章：计算机视觉与图像表示基础

> 本章目标：理解一张图片在计算机和神经网络中是什么，掌握像素、通道、张量、卷积、特征图、Patch 与视觉 Token，并能计算分辨率变化对 VLM 计算量的影响。

## 2. 图片在计算机中是什么

### 2.1 图片文件不等于像素张量

硬盘中的 JPEG、PNG 是带格式和压缩的数据。模型不能直接对 JPEG 文件字节进行通常意义上的视觉理解，需要先解码：

```text
JPEG/PNG 文件
   ↓ 图片解码器
二维像素网格
   ↓ 转换数据类型、调整维度
模型输入张量
```

JPEG 通常是有损压缩；PNG 通常支持无损压缩和透明通道。相同画面保存成不同格式，文件大小不同，解码后的像素也可能略有差异。

### 2.2 分辨率

一张 `1920 × 1080` 图片通常表示：

- 宽度 `W = 1920`；
- 高度 `H = 1080`；
- 总像素数 `1920 × 1080 = 2,073,600`，约 207 万像素。

“分辨率高”通常意味着像素网格更密，但不保证图片更清晰。失焦、压缩、噪声或放大插值都可能让高分辨率图片缺少真实细节。

### 2.3 RGB 通道

常见彩色图片用红、绿、蓝三个通道表示：

```text
某个像素 = [R, G, B]
红色      = [255, 0, 0]
黑色      = [0, 0, 0]
白色      = [255, 255, 255]
```

8 位图像的每个通道一般取 `0～255`。一个 RGB 像素有三个数，不是一个数。

### 2.4 其他通道形式

| 类型 | 通道数 | 说明 |
|---|---:|---|
| 灰度图 | 1 | 每个像素主要表示亮度 |
| RGB | 3 | 红、绿、蓝 |
| RGBA | 4 | RGB 加透明度 Alpha |
| 深度图 | 1 或更多 | 像素表示距离或相对深度 |
| 多光谱图像 | 多于 3 | 可包含红外等人眼不可见波段 |

模型的第一层必须知道输入通道数。用为 RGB 训练的模型处理灰度、RGBA 或多光谱图像时，需要适配输入。

## 3. 图像张量与维度顺序

### 3.1 HWC 与 CHW

图片库常用：

```text
H × W × C
高 × 宽 × 通道
```

PyTorch 视觉模型常用：

```text
C × H × W
通道 × 高 × 宽
```

加入 Batch 后通常为：

```text
B × C × H × W
```

例如 8 张 `224 × 224` RGB 图片组成的 Batch：

```text
[8, 3, 224, 224]
```

维度顺序错误可能不立即报错，却会让模型把空间维度当成通道，产生完全错误的结果。

### 3.2 数据类型和取值范围

原始图像常是 `uint8`，取值 `0～255`。模型计算通常使用 `float32`、`float16` 或 `bfloat16`。

常见转换：

```text
uint8: 0～255
   ↓ 除以 255
float: 0.0～1.0
   ↓ 按通道 Normalize
模型期望的数值分布
```

Torchvision 的 `ToTensor` 传统接口可把符合条件的 `uint8` 图片从 HWC 转为 CHW，并缩放到 `[0,1]`。但不同处理器和数据类型行为可能不同，不能只凭函数名称猜测。

### 3.3 内存粗算

一张未经压缩的 `224 × 224 × 3` 图片：

```text
uint8   : 224 × 224 × 3 × 1 Byte ≈ 147 KB
float32 : 224 × 224 × 3 × 4 Byte ≈ 588 KB
float16 : 224 × 224 × 3 × 2 Byte ≈ 294 KB
```

模型训练显存远大于输入张量本身，因为还要保存中间激活、梯度、优化器状态和注意力矩阵。

## 4. 图像预处理

图像预处理决定“模型实际上看见了什么”。

```text
原图
 ↓ 颜色格式转换
RGB 图片
 ↓ Resize / Crop / Pad
固定或受控尺寸
 ↓ 转成张量
浮点像素
 ↓ Normalize
模型输入
```

### 4.1 Resize：缩放

Resize 改变图片尺寸。常见方式：

- 强制缩放到固定高宽：可能改变长宽比，使物体变形；
- 短边缩放到目标值：保持长宽比，但长边尺寸不固定；
- 限制最长边或总像素：适合动态分辨率 VLM。

缩放需要插值。Nearest、Bilinear、Bicubic 的速度和视觉效果不同。小文字经过缩小后可能彻底消失。

### 4.2 Crop：裁剪

- Center Crop：保留中心区域；
- Random Crop：训练时随机取区域；
- Random Resized Crop：随机裁剪后缩放到目标尺寸。

裁剪可以增加训练变化，但可能把关键对象、文字或边界框裁掉。对 OCR、文档和 Grounding 数据，必须同步变换标注。

### 4.3 Pad：填充

Pad 在图片周围补像素，可以保留完整画面和长宽比，但会引入无内容区域。模型需要知道填充区域不能当作真实视觉证据。

### 4.4 Normalize：归一化

常见按通道公式：

```text
x_normalized = (x - mean) / std
```

这里的 `mean` 和 `std` 通常来自预训练配置。它不是简单把所有值限制在 `[0,1]`，而是调整每个通道的中心和尺度。

如果视觉编码器预训练使用一套均值和标准差，推理时换成另一套，输入分布会偏移。应使用模型官方 Image Processor 配置。

### 4.5 预处理不是越多越好

| 操作 | 可能收益 | 可能伤害 |
|---|---|---|
| 随机裁剪 | 增强位置鲁棒性 | 丢失主体或文字 |
| 水平翻转 | 扩充自然图片变化 | 文字镜像、左右关系被反转 |
| 颜色扰动 | 增强光照鲁棒性 | 颜色问答标签失真 |
| 模糊/压缩 | 增强低质量图片鲁棒性 | 小字和细节丢失 |
| 旋转 | 增强方向变化 | 文档阅读顺序变化 |

多模态数据增强必须保持图片、问题和答案语义一致。

## 5. 什么是图像特征

像素是低层输入，特征是模型为了任务学习出的内部表示。

```text
像素
 ↓
边缘、颜色变化
 ↓
纹理、角点、局部形状
 ↓
物体部件
 ↓
对象和场景语义
```

这是帮助理解的抽象，不表示每层只能表示一种固定内容。深度网络中的特征通常分布在多个通道和位置中。

### 5.1 全局特征

把整张图压缩为一个向量：

```text
图片 → [全局向量]
```

适合分类和检索，但可能损失对象位置与小细节。

### 5.2 局部或密集特征

为多个空间位置分别保留向量：

```text
图片 → H' × W' × D 特征网格
```

适合检测、分割、Grounding、OCR，也常被转成视觉 Token 送入 LLM。

## 6. 卷积到底做了什么

### 6.1 卷积核

卷积核是一个小型可学习权重窗口，例如 `3 × 3`。它在图片或特征图上滑动，对局部区域做加权求和。

```text
输入局部区域          卷积核
a b c                 w1 w2 w3
d e f        ×        w4 w5 w6
g h i                 w7 w8 w9

输出 = a·w1 + b·w2 + ... + i·w9 + bias
```

训练前，权重通常随机初始化；训练后，某些卷积核会对边缘、纹理或更复杂模式产生强响应。

### 6.2 权重共享

同一个卷积核在整张图的不同位置重复使用：

- 参数量较少；
- 能在不同位置检测相似局部模式；
- 引入“局部性”和近似平移等变的归纳偏置。

### 6.3 输入通道与输出通道

一个真正的 RGB 卷积核不是单纯 `3×3`，而是覆盖输入通道：

```text
单个卷积核形状 = 3 × 3 × C_in
多个卷积核产生 C_out 个输出通道
```

参数量（不计 Bias）：

```text
K_h × K_w × C_in × C_out
```

例如 `3×3`、输入 3 通道、输出 64 通道：

```text
3 × 3 × 3 × 64 = 1,728 个权重
```

## 7. Stride、Padding 与输出尺寸

一维方向的卷积输出尺寸：

```text
out = floor((in + 2P - K) / S) + 1
```

- `K`：Kernel Size；
- `S`：Stride；
- `P`：Padding。

示例：输入 `224`，卷积核 `3`，Stride `1`，Padding `1`：

```text
out = floor((224 + 2 - 3) / 1) + 1 = 224
```

若 Stride 改为 `2`：

```text
out = floor((224 + 2 - 3) / 2) + 1 = 112
```

因此 Stride 2 会让高宽大约减半，空间位置数约变成四分之一。

## 8. 特征图、下采样与感受野

### 8.1 特征图

卷积层输出常写为：

```text
C_out × H_out × W_out
```

每个通道是一张二维响应图，多个通道共同描述不同视觉模式。

### 8.2 下采样

下采样减少空间尺寸：

```text
224×224 → 112×112 → 56×56 → 28×28 → 14×14 → 7×7
```

收益：减少计算、扩大高层单元覆盖范围、增强抽象表示。代价：小目标、小字和精确位置可能丢失。

### 8.3 感受野

某个特征位置能受到输入图片多大区域影响，称为感受野。

连续堆叠卷积后，深层特征可以间接看到更大范围。理论感受野不等于有效感受野：虽然理论上覆盖整图，实际贡献可能集中在部分区域。

### 8.4 VLM 为什么关心下采样

如果视觉编码器过度下采样：

- 文档中的小字会混在一起；
- 小物体消失；
- 精确定位变差；
- 送入 LLM 的 Token 少、速度快。

保留高分辨率特征则方向相反。因此视觉能力和推理成本之间存在直接权衡。

## 9. 分类、检测和分割

### 9.1 图像分类

```text
整张图片 → 一个或多个类别
```

例如“猫”。模型主要需要全局语义，不一定要输出猫的位置。

### 9.2 Object Detection

```text
整张图片 → 多个 {类别, 边界框, 置信度}
```

检测既要知道是什么，也要知道在哪里。

### 9.3 语义分割

```text
每个像素 → 一个语义类别
```

同类的多个对象可以使用同一类别。

### 9.4 实例分割

除了像素类别，还要区分同类的不同实例。例如两个人要得到两个独立掩码。

### 9.5 它们与 VLM 的关系

| 传统任务 | VLM 中的对应能力 |
|---|---|
| 分类 | 开放词汇识别、VQA |
| 检测 | Grounding、坐标生成 |
| 分割 | Referring Segmentation |
| OCR | 文字读取和文档问答 |

VLM 用语言统一接口，但并不消除底层感知难度。

## 10. 从图片到 Patch

Vision Transformer 通常把图像切成不重叠的方形 Patch。

```text
224 × 224 图片，Patch = 16 × 16

横向：224 / 16 = 14
纵向：224 / 16 = 14
总数：14 × 14 = 196 个 Patch
```

每个 RGB Patch 原始元素数：

```text
16 × 16 × 3 = 768
```

把这个长度为 768 的数据经过线性投影，就得到一个维度为 `D` 的 Patch Embedding。

### 10.1 通用公式

当高宽都能被 Patch Size 整除时：

```text
N = (H / P_h) × (W / P_w)
```

如果还加入 CLS Token：

```text
序列长度 = N + 1
```

生成式 VLM 不一定把 CLS Token 送入 LLM，往往会保留多个局部 Patch Token。

### 10.2 Patch Embedding 与卷积的关系

不重叠 Patch Embedding 可以用一个 Kernel Size 和 Stride 都等于 Patch Size 的卷积实现。因此“CNN”和“ViT”并非完全互斥，许多现代视觉网络会混合两者思想。

---

## 11. 必做手算：448×448、Patch 14

### 11.1 Token 数

```text
H = 448
W = 448
P = 14

每行 Patch 数 = 448 / 14 = 32
每列 Patch 数 = 448 / 14 = 32
Patch Token 数 = 32 × 32 = 1,024
```

如果加入一个 CLS Token，ViT 内部序列长度为 `1,025`；如果还加入其他特殊 Token，需要继续增加。

### 11.2 与 224×224 对比

```text
224×224, Patch 14 → 16×16 = 256 Tokens
448×448, Patch 14 → 32×32 = 1,024 Tokens
```

高宽都翻倍，像素数量和 Token 数都变为 4 倍。

### 11.3 注意力为什么约变成 16 倍

标准全局 Self-Attention 的注意力矩阵大小与 `N²` 成正比：

```text
256²   = 65,536
1,024² = 1,048,576

1,048,576 / 65,536 = 16
```

因此在 Patch Size 不变时：

```text
图片高宽各 ×2
→ 像素数 ×4
→ Patch Token ×4
→ 全局注意力矩阵元素 ×16
```

注意：整个视觉编码器 FLOPs 不一定恰好增长 16 倍，因为线性层、Patch Embedding、实现方式和局部注意力也占计算；但标准全局注意力中与 `N²` 相关的部分确实如此增长。

### 11.4 进入 LLM 后的额外成本

假设视觉编码器输出 1,024 个视觉 Token，再加 1,000 个文本 Token：

```text
总上下文约 2,024 Tokens
```

视觉 Token 不仅在视觉编码器中产生计算，还会增加 LLM Prefill 的序列长度、KV Cache 和延迟。因此很多 VLM 使用 Patch Merge、Pooling、Resampler 或 Token Compression。

## 12. Patch Size 的权衡

同样是 `448×448` 图片：

| Patch Size | 网格 | Patch Token 数 | 特点 |
|---:|---:|---:|---|
| 32 | 14×14 | 196 | 快，但细节较粗 |
| 16 | 28×28 | 784 | 折中 |
| 14 | 32×32 | 1,024 | 细节更多，成本更高 |
| 8 | 56×56 | 3,136 | 细粒度强，全局注意力昂贵 |

更小的 Patch 不自动意味着更高准确率。模型必须有对应的预训练、位置编码和计算能力。

## 13. 固定分辨率、动态分辨率与切块

### 13.1 固定分辨率

所有图片缩放/裁剪到固定尺寸，例如 `224×224` 或 `336×336`。

优点：Batch 容易组织、计算稳定。缺点：长图变形、文档小字丢失、极端长宽比不友好。

### 13.2 保持长宽比并填充

图片缩放后 Pad 到固定画布。保留完整内容，但存在空白区域和无效 Token。

### 13.3 动态分辨率

根据原图长宽比和像素预算选择尺寸，让不同图片产生不同 Token 数。

优点：更适合文档、长图和小目标。难点：Batch 中序列长短不一，显存和延迟更难预测。

### 13.4 图像切块

```text
高分辨率原图
  ├─ 全局缩略图
  ├─ 左上局部块
  ├─ 右上局部块
  ├─ 左下局部块
  └─ 右下局部块
```

局部块保留细节，全局图提供整体关系。但重叠切块会重复编码内容，块过多会让视觉 Token 爆炸。

## 14. 数据增强为何需要任务感知

### 14.1 分类中的增强

分类只关心主要类别，随机裁剪、翻转和颜色扰动通常较常见。

### 14.2 OCR 中的增强

可以模拟模糊、透视、低光和压缩，但水平翻转通常会把文字变成镜像，答案随之失效。

### 14.3 Grounding 中的增强

对图片裁剪、缩放、翻转时，边界框或点坐标必须同步变换：

```text
变换图片但不变换坐标 = 制造错误监督信号
```

### 14.4 VQA 中的增强

问题“左边的人穿什么颜色”在水平翻转后，左右语义可能改变；颜色扰动会破坏颜色类问题。应根据问题类型决定是否增强。

## 15. CNN 与 ViT 的直观比较

| 维度 | CNN | ViT |
|---|---|---|
| 基本单元 | 卷积核 | Patch Token + Attention |
| 先验 | 强局部性、权重共享 | 结构先验相对较弱 |
| 全局关系 | 多层堆叠逐步扩大范围 | 全局注意力可直接交互 |
| 数据需求 | 通常较有样本效率 | 原始 ViT 更依赖大规模预训练 |
| 输出形式 | 多尺度特征图 | Token 序列或特征网格 |
| 高分辨率成本 | 随结构增长 | 全局注意力可能受 `N²` 影响 |
| VLM 使用 | 可作视觉骨干 | 当前生成式 VLM 更常见 |

现代边界并不绝对：ConvNeXt 吸收 Transformer 的设计经验；Swin 等视觉 Transformer 又引入层级结构和局部窗口。应看实际算子和数据流，不只看模型名称。

## 16. 常见图像问题怎样影响 VLM

| 问题 | 视觉影响 | VLM 可能表现 |
|---|---|---|
| 低分辨率 | 小物体和文字消失 | OCR 错、计数错 |
| JPEG 压缩 | 边缘和纹理出现伪影 | 小字混淆 |
| 运动模糊 | 轮廓不清 | 动作/对象误判 |
| 过曝/欠曝 | 局部信息饱和或丢失 | 颜色和对象识别错 |
| 遮挡 | 对象只有部分可见 | 按语言先验补全并幻觉 |
| 极端长宽比 | 强制缩放导致变形 | 文档和长图理解下降 |
| 图片旋转 | 文字方向改变 | OCR 与版面顺序错 |
| 小目标 | 下采样后不足一个有效 Token | 完全漏检 |

模型输出流畅不代表输入细节仍然存在。遇到失败案例时，应同时保存原图、模型实际 resize 后的图片、视觉 Token 配置和 Prompt。

## 17. 一个端到端尺寸示例

假设输入一张 `1920×1080` 图片，处理器要求保持长宽比并把短边缩到 448，然后裁剪为 `448×448`：

```text
原图 1920×1080
  ↓ 短边缩放到 448
约 796×448
  ↓ 中心裁剪
448×448
  ↓ Patch Size 14
32×32 = 1,024 Patch Tokens
```

风险：原图左右两侧内容被裁掉。如果用户问的是画面最左侧物体，模型实际上根本没有看到。

另一种方式是保留 `796×448` 并 Pad 到可整除尺寸：

```text
约 798×448（示意）
→ 57×32 = 1,824 Patch Tokens
```

内容更完整，但 Token 更多。工程选择本质上是在内容完整性、细节和成本之间权衡。

## 18. 小型代码实验

下面的代码只演示张量和 Patch 数，不依赖具体 VLM：

```python
import torch

batch = 2
channels = 3
height = 448
width = 448
patch = 14

images = torch.randn(batch, channels, height, width)
num_patches = (height // patch) * (width // patch)

print("image tensor:", images.shape)
print("patch grid:", height // patch, "x", width // patch)
print("patch tokens:", num_patches)

# 把图片切成不重叠 Patch，仅演示形状
patches = images.unfold(2, patch, patch).unfold(3, patch, patch)
print("unfolded:", patches.shape)
```

预期核心结果：

```text
image tensor: [2, 3, 448, 448]
patch grid: 32 x 32
patch tokens: 1024
```

真实 ViT 还会重排 Patch，并通过线性层映射到隐藏维度。

## 19. 常见误区

1. **像素越多一定越清楚**：原始采集质量决定真实信息，放大不能创造可靠细节。
2. **RGB 图片每个像素只有一个数**：通常有三个通道值。
3. **JPEG 文件大小就是模型显存**：文件压缩大小和解码张量、激活显存是不同概念。
4. **Normalize 就是除以 255**：除以 255 和按均值/标准差归一化是两步。
5. **Resize 不改变语义**：强制改变长宽比、缩小文字都可能损害语义。
6. **随机翻转适合所有任务**：文字、左右关系、坐标任务可能被破坏。
7. **卷积核是人工写好的边缘检测器**：现代 CNN 卷积核通常由数据训练得到。
8. **每个特征通道对应一个人类概念**：神经表示通常是分布式的。
9. **下采样只有收益**：它减少计算，也会损失位置和细节。
10. **Patch 就等于语言中的词**：二者都可成为序列元素，但语义形成和训练方式不同。
11. **高宽翻倍只增加两倍计算**：Token 变 4 倍，全局注意力相关部分可变约 16 倍。
12. **视觉编码器输出 Token 数就是 LLM 最终接收数**：连接器可能合并、压缩或重采样。

## 20. 本章总结

```text
图片文件先解码成 H×W×C 像素网格，
再经过缩放、裁剪、张量转换和归一化。

CNN 用局部卷积逐层形成特征图；
ViT 把图片切成 Patch 并转为 Token 序列。

视觉细节与成本的核心矛盾：
更高分辨率 / 更小 Patch
→ 更多视觉 Token
→ 更强细节潜力
→ 更高视觉编码和 LLM Prefill 成本。

448×448、Patch 14 产生 1,024 个 Patch Token；
图片高宽各翻倍时，Token 数变 4 倍，
标准全局注意力矩阵规模变约 16 倍。
```
