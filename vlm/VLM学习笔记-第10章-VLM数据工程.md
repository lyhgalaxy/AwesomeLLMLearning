# 第 10 章：VLM 数据工程

> VLM 数据不是“图片路径加一句话”这么简单。图片质量、视觉可回答性、坐标变换、视频时间、对话模板、版权和 Benchmark 污染都会直接决定模型能力。

## 1. 数据全景

```text
原始来源
网页图文 / 文档 / 视频 / 标注集 / GUI轨迹 / 合成数据
  ↓
下载解码 → 安全与许可 → 去重 → 质量过滤 → 图文相关性
  ↓
任务化
Caption / VQA / OCR / Grounding / Video / Preference / RL
  ↓
统一 Schema + Chat Template + Image Processor
  ↓
按阶段和能力配比
Pretrain → Alignment → CPT → SFT → DPO/RL
  ↓
独立验证、污染审计、失败分析
```

## 2. 样本的三个层次

### 2.1 资产层

保存图片/视频本体、URI、哈希、尺寸、格式、来源、许可证、采集日期和安全标签。

### 2.2 语义层

Caption、OCR、对象框、文档版面、时间戳、问答、推理轨迹、质量分和语言。

### 2.3 训练层

根据模型 Processor 转为消息、图片列表、Chosen/Rejected 或 Prompt-only。资产与训练格式分开，可重复生成不同模板。

## 3. 通用图文对

```json
{
  "image": "images/0001.jpg",
  "caption": "一只狗在草地上追逐红色飞盘",
  "source": "...",
  "license": "...",
  "quality": 0.93
}
```

用于 CLIP/SigLIP 时是一对正样本；用于生成预训练时 Caption 是目标文本。短 Alt Text 规模大但噪声高，人工/高质量合成 Caption 信息密度高但成本大。

## 4. 交错图文数据

```text
段落1 → 图片1 → 段落2 → 图片2 → 段落3
```

它教模型理解多图与长文关系，比孤立图文对更接近网页、教材和论文。必须保留文档顺序、图片位置、局部上下文和跨图引用，同时过滤导航栏、广告和错误图片。

代表开放数据工作包括 OBELICS、MMC4 等；实际使用需核对资产可访问性、许可和过滤策略。

## 5. 多模态对话与 SFT 格式

推荐逻辑结构：

```json
{
  "images": ["a.jpg"],
  "messages": [
    {"role": "user", "content": [
      {"type": "image"},
      {"type": "text", "text": "请描述图片"}
    ]},
    {"role": "assistant", "content": [
      {"type": "text", "text": "一只狗正在追飞盘。"}
    ]}
  ]
}
```

不同框架字段不同，但语义应明确图片占位顺序与消息角色。只在 Assistant 答案 Token 上计算 Loss 时，要正确设置 Label Mask。

## 6. OCR 与文档数据

需要记录：

- 页面图片、原始尺寸和方向；
- 文字内容、语言、行/块/表格结构；
- Bounding Box/Polygon；
- 阅读顺序；
- 字段键值、问答与证据区域；
- 扫描质量、旋转、模糊和遮挡。

不要只用 OCR 引擎输出再当真值，否则模型会继承引擎错误。文档切块时需保存页码和跨页关系。

## 7. Grounding 数据

```json
{
  "image": "street.jpg",
  "expression": "左侧穿红衣服的人",
  "bbox_xyxy": [42, 31, 188, 420],
  "width": 1280,
  "height": 720
}
```

必须说明坐标格式：`xyxy`、`xywh`、归一化 `[0,1]`、离散 `[0,1000]` 或真实像素。Resize/Crop/Flip 后同步变换坐标，并检查框仍有效。

负样本同样重要：当描述对象不存在时，模型应拒绝定位，而不是随便生成一个框。

## 8. 视频数据

除视频文件外，还要保存：FPS、时长、时间戳、字幕、镜头和事件区间。

```text
原视频 30 FPS
 → 训练采样 1 FPS
 → 每帧绑定真实时间 t
 → 问答/事件答案引用 [start,end]
```

如果只保存帧序号而忽略原 FPS，模型无法学习真实时间。字幕可能直接泄漏答案，应分别评测带字幕与不带字幕。

## 9. 多图与比较数据

每个图片占位符必须对应确定资产：

```json
{"images":["before.jpg","after.jpg"], "question":"第二张发生了什么变化？"}
```

质检需交换图片顺序再次生成答案，防止模型只记“第一/第二”模板。还应包含“相同”“无法比较”“证据不足”等样本。

## 10. 推理与可验证数据

视觉数学、图表、几何等任务最好保存：最终答案、结构化中间量、证据区域和可执行验证器。

推理文本可能含教师幻觉，不能把长 CoT 自动视为高质量。训练时可选择隐藏推理、短理由、步骤监督或只用结果奖励，取决于模型与目标。

## 11. 偏好数据

DPO/Reward Model 样本：

```json
{
  "image": "invoice.png",
  "prompt": "发票总额是多少？",
  "chosen": "总额为 128.50 元。",
  "rejected": "总额为 182.50 元。"
}
```

Chosen/Rejected 应主要在目标维度有差异；若长度、语气和正确性同时不同，模型难以知道偏好原因。可标注事实性、视觉依赖、格式、安全、完整性等维度。

## 12. RL Prompt 数据

GRPO/PPO 通常从 Prompt-only 开始，运行当前模型产生多个回答，再由规则、模型或环境给奖励。样本至少包含图片、问题、可验证答案/环境、评分器版本和难度。

训练集不能只有容易题，否则组内回答奖励相同，GRPO 优势信号接近零。

## 13. GUI Agent 轨迹

```text
目标 + screenshot_t + history
 → action_t(click/type/scroll)
 → screenshot_t+1 + observation
 → ... → final success
```

需要记录坐标系、窗口尺寸、DPI、工具 Schema、动作结果和任务终态。隐私清洗尤其重要，因为截图可能含账号、邮件和个人信息。

## 14. 数据清洗流水线

1. 文件可解码、格式与尺寸检查；
2. 极小图、纯色图、损坏图过滤；
3. NSFW、暴力、个人信息和恶意内容检测；
4. 文本语言、长度、乱码和模板过滤；
5. 图文相关性打分；
6. OCR/Caption/标注一致性检查；
7. 精确与近重复去除；
8. Benchmark 污染检查；
9. 质量分层而非只有删除/保留；
10. 人工抽检和错误率估计。

自动模型过滤可能带偏差，必须保存过滤器版本、阈值和抽检结果。

## 15. 去重

- 文件 Hash：完全相同字节；
- 解码像素 Hash：不同文件编码但同画面；
- Perceptual Hash：缩放/轻微压缩近重复；
- 视觉 Embedding：裁剪、加水印等语义近重复；
- 文本 MinHash/Embedding：Caption 与问题模板重复；
- 跨训练/测试集去重：防 Benchmark 泄漏。

去重不是越强越好：商品不同角度、视频相邻帧和文档页有真实关系，应按数据类型设规则。

## 16. 数据合成

```text
真实图片 + Caption/OCR/框
 → 教师模型生成问题、答案、推理或拒答
 → 规则验证 + 多模型一致性 + 人工抽检
```

优势是快速扩展任务；风险是教师幻觉、语言风格单一、答案从元数据泄漏、模型闭环偏差。应保留 provenance、教师版本、Prompt 和验证结果。

## 17. 数据配比

按样本数配比会误导：一段视频可能产生上万视觉 Token，一条短文本只有几十 Token。建议同时统计：

- 样本数；
- 图片/视频数；
- 文本 Token；
- 视觉 Token；
- 训练 FLOPs；
- 每类任务有效 Batch；
- 每来源重复 Epoch。

配比目标是能力覆盖与训练稳定，不是让每类数据数量相等。

## 18. 数据量与模型参数

不存在通用“每 B 参数需要 X 张图片”公式。影响因素：是否从头训练 ViT/LLM、可训练参数、数据质量、分辨率、视觉 Token、语言覆盖、任务复杂度和计算预算。

实践原则：

- 从头预训练通用模型：需要大规模、多样数据与 Scaling 实验；
- 冻结骨干训练连接器：数量可更小，但必须覆盖接口语义；
- SFT：高质量与任务覆盖通常比盲目增加模板重复更重要；
- 领域 LoRA：从小规模高质量集开始画学习曲线；
- RL：关键是可验证性、难度和奖励方差。

## 19. 开源数据集分类示例

| 类别 | 示例 | 注意点 |
|---|---|---|
| 通用图文 | LAION、COYO、CC3M/12M | 原图可用性、噪声、许可 |
| Caption/VQA | COCO、VQAv2、GQA | 答案先验与固定风格 |
| 交错图文 | MMC4、OBELICS | 网页顺序和资产许可 |
| OCR/文档 | TextVQA、DocVQA、ChartQA | 小字、版面、坐标 |
| Grounding | RefCOCO 系列、Visual Genome | 框格式和重复对象 |
| 视频 | WebVid、VideoChat 数据、Video-MME相关集 | 帧、字幕、时间许可 |
| 指令 | LLaVA-Instruct、M3IT | 合成教师偏差 |
| 偏好 | RLAIF-V 等 | 偏好维度和 Judge 偏差 |

列表不是许可结论，下载和商用前必须逐个核对数据卡与原资产条款。

## 20. 切分与污染

测试集应按原始资产/文档/视频分组切分，不能把同一视频相邻帧放入训练和测试。检查图片近重复、问题改写、答案模板和网页来源重合。

维护一份禁止训练的 Benchmark Registry，在采集、合成和混合阶段都过滤。

## 21. 数据质量仪表盘

至少报告：来源占比、语言、分辨率、长宽比、Caption 长度、视觉/文本 Token、重复率、图文相似度、OCR 字符分布、框面积、视频时长、任务难度、安全标签和人工抽检正确率。

## 22. 常见误区

1. 图片能打开就算合格；
2. Caption 越长越好；
3. 合成数据天然准确；
4. 图片数可以代表训练计算；
5. 坐标无需保存原图尺寸；
6. 视频帧序号等于真实时间；
7. 去重只用文件 Hash；
8. 公开下载等于可任意商用；
9. SFT 数据越多必然越强；
10. Benchmark 题目不出现原文就没有污染。

## 23. 总结与复习

```text
VLM 数据工程 = 资产治理 + 跨模态语义 + 训练格式 + 配比 + 污染控制。
数据规模要同时用样本、视觉/文本 Token 和算力衡量。
任何图片变换都要维护文字、坐标、时间和答案的一致性。
```

复习：资产层为何与训练层分开？Grounding 必须保存什么？为何视频要真实时间？DPO 对如何构造？GRPO Prompt 需要什么？怎样做跨模态去重？
